# WHMCS Customer Billing Portal

Laravel 12 + Blade customer billing portal powered by the WHMCS API.

## cPanel / Shared Hosting

Built for normal cPanel shared hosting. No Docker, Supervisor, Redis or VPS-only service is required for the core portal.

### Requirements

- PHP 8.2 or 8.3
- MySQL/MariaDB
- HTTPS
- Laravel PHP extensions
- Composer is recommended for building, but production can use an uploaded vendor directory

### Install

1. Upload the complete project, including `vendor/`, to a private application directory.
2. Point a cPanel subdomain/document root to the project's `public/` directory.
3. Open `/install`.
4. Enter MySQL database details.
5. The installer creates `.env`, generates `APP_KEY`, and runs migrations.
6. Open `/dashboard`.
7. Configure WHMCS, bKash, checkout, refund and admin settings from Admin → Settings.

After successful installation, the installer is locked by `storage/app/installed`.

### Existing resellnom.com website

Do not replace the existing `public_html` site.

Recommended:

```
/home/ACCOUNT/
├── public_html/       # existing resellnom.com
└── billing-portal/    # this Laravel project
    ├── app/
    ├── bootstrap/
    ├── config/
    ├── database/
    ├── public/
    ├── resources/
    ├── routes/
    ├── storage/
    └── vendor/
```

The simplest cPanel deployment is a subdomain such as `billing.resellnom.com` pointing to `billing-portal/public`.

If the required public URLs are exactly `resellnom.com/dashboard` and `resellnom.com/cart`, the existing root site's Apache rewrite must route those paths into this Laravel application's `public/index.php`. Do not overwrite the existing root `.htaccess` without checking the current website rules.

### Runtime settings

WHMCS, bKash, refund, checkout and master-admin runtime settings are managed from Admin → Settings.

Sensitive settings are encrypted in the database using Laravel's application key.

Only Laravel's application key and database connection are environment-level values generated by the installer.

### Permissions

Laravel must be able to write to:

- `storage/`
- `bootstrap/cache/`

Use normal cPanel permissions first (usually 755 directories / 644 files).

### Production

Use HTTPS, PHP 8.2/8.3, a real MySQL database, and merchant production credentials only after testing the complete payment callback/refund flow.
